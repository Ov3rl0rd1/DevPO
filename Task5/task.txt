РАЗРАБОТКА ПРОФЕССИОНАЛЬНЫХ ПРИЛОЖЕНИЙ
Практическая работа № 5
«Система учёта сельскохозяйственной техники на PySide6 + QML»

Разработать настольное приложение для учёта техники сельскохозяйственного предприятия. Пользователь должен видеть зарегистрированную технику, добавлять новые машины, редактировать сведения о существующих объектах, удалять записи и находить нужную технику.
Примеры объектов учёта: трактор, комбайн, грузовой автомобиль, опрыскиватель, сеялка, культиватор, погрузчик и другая техника.
1. Данные об объекте техники
Каждая единица техники должна содержать как минимум следующие сведения:
Поле	Пример / назначение
Название / модель	Например: Кировец К-744Р4, CLAAS LEXION 770
Тип техники	Трактор, комбайн, автомобиль, сеялка, опрыскиватель и т. п.
Инвентарный номер	Строковое значение, уникальное для объекта
Год выпуска	Числовое значение
Состояние	Исправна / требует обслуживания / в ремонте / списана
Место эксплуатации или подразделение	Например: поле № 3, машинный двор, бригада № 2
Ответственный	ФИО или краткое имя ответственного сотрудника
Наработка / моточасы	Числовое значение
Активна в эксплуатации	Логическое значение
Уровень технического состояния	Например, значение от 0 до 100

Допускается расширение набора полей. Например, можно добавить стоимость, государственный номер, дату последнего ТО, вид топлива, мощность двигателя или примечание.
2. Структура приложения
Приложение должно быть разделено как минимум на Python-часть и QML-интерфейс. Не следует хранить всю логику в одном Main.qml.
project/
├── main.py
├── models/
│   ├── equipment.py
│   └── equipment_model.py
├── services/
│   └── storage.py
├── data/
│   └── equipment.json
└── qml/
    ├── Main.qml
    ├── EquipmentForm.qml
    └── EquipmentCard.qml
Структура может отличаться, но разделение ответственности должно сохраняться: QML отвечает за отображение и пользовательские действия, Python – за данные, проверки, изменение коллекции и сохранение.
3. Класс объекта техники
Создайте Python-класс, описывающий одну единицу техники. Можно использовать обычный класс или dataclass. Не требуется копировать пример дословно – набор полей должен соответствовать вашему интерфейсу.
from dataclasses import dataclass

@dataclass
class Equipment:
    id: int
    name: str
    category: str
    inventory_number: str
    year: int
    status: str
    location: str
    responsible: str
    hours: int
    active: bool
    condition: int
Объект Equipment описывает одну запись. Сам список объектов не должен храниться внутри каждого Equipment: коллекцией управляет отдельная модель.
4. Модель списка техники
Для передачи коллекции из Python в QML рекомендуется использовать QAbstractListModel. Каждое поле, которое требуется показать в QML, должно быть доступно через роль модели.
class EquipmentModel(QAbstractListModel):
    IdRole = Qt.UserRole + 1
    NameRole = Qt.UserRole + 2
    CategoryRole = Qt.UserRole + 3
    StatusRole = Qt.UserRole + 4
    InventoryRole = Qt.UserRole + 5

    def __init__(self, items=None):
        super().__init__()
        self._items = items or []

    def rowCount(self, parent=QModelIndex()):
        return len(self._items)
Самостоятельно определить остальные роли, реализовать roleNames() и data(), а затем методы изменения коллекции.
5. Главное окно
В главном окне должны присутствовать:
·	заголовок приложения;
·	поле поиска;
·	фильтр по типу или состоянию техники;
·	список зарегистрированной техники;
·	кнопка «Добавить технику»;
·	возможность открыть запись для редактирования;
·	возможность удалить запись;
·	понятное сообщение, если список пуст.
Для отображения списка используйте ListView. Одна строка или карточка списка должна показывать минимум название техники, тип, инвентарный номер и текущее состояние.
ListView {
    id: equipmentList
    anchors.fill: parent
    model: equipmentModel

    delegate: EquipmentCard {
        equipmentName: model.name
        category: model.category
        status: model.status
        inventoryNumber: model.inventoryNumber
    }
}
EquipmentCard.qml желательно оформить как отдельный компонент. В карточке разместите кнопки или действия «Редактировать» и «Удалить».
6. Добавление техники
Элемент	Пример применения
TextField	Название, инвентарный номер, место эксплуатации, ответственный
ComboBox	Тип техники и состояние
SpinBox / числовой ввод	Год выпуска, моточасы
CheckBox / Switch	Техника находится в эксплуатации
Slider	Условная оценка технического состояния 0–100
Button	Сохранить / Очистить / Отмена
При нажатии «Добавить технику» должна открываться форма. Можно использовать отдельную Page, Dialog или Popup.
7. Валидация
Нельзя сохранять заведомо некорректную запись. Минимальные проверки:
·	название техники не пустое;
·	инвентарный номер не пустой;
·	инвентарный номер не повторяет номер уже существующей техники;
·	год выпуска находится в разумном диапазоне;
·	моточасы не могут быть отрицательными;
·	оценка состояния находится в диапазоне 0-100.
Важно: проверка только в QML недостаточна. Критические правила должны проверяться и в Python, поскольку именно Python-часть изменяет модель и сохраняет данные.
8. Редактирование записи
Пользователь должен иметь возможность выбрать существующую технику и изменить её данные. При открытии формы редактирования поля должны быть заполнены текущими значениями объекта.
1.	Выбрать технику в списке.
2.	Нажать «Редактировать».
3.	Передать идентификатор выбранного объекта в Python или форму.
4.	Заполнить поля текущими значениями.
5.	Изменить необходимые сведения.
6.	После сохранения обновить существующий объект, а не создавать новый.
7.	Уведомить QML-модель об изменении, чтобы карточка обновилась без перезапуска приложения.
При реализации через QAbstractListModel необходимо корректно уведомить представление об изменившихся данных, например с помощью dataChanged.
9. Удаление техники
Для каждой записи должна быть доступна операция удаления. Перед удалением желательно показать подтверждение, чтобы пользователь не удалил объект случайно.
Удалить «Кировец К-744Р4»?

[Отмена]    [Удалить]
После подтверждения запись удаляется из Python-модели, список в QML обновляется, а изменения сохраняются в файл.
10. Поиск и фильтрация
Добавьте поиск хотя бы по названию или инвентарному номеру. Также должен присутствовать минимум один фильтр — например, по типу техники или её состоянию.
Пример поведения:
·	пользователь вводит «Кировец» – остаются записи, содержащие это слово;
·	выбирает «В ремонте» – отображается только техника с соответствующим состоянием;
·	очищает поиск и выбирает «Все» – снова отображается полный список.
Повышенный уровень: реализовать фильтрацию через QSortFilterProxyModel, а не вручную формировать второй список.
11. Сохранение данных
Данные не должны исчезать после закрытия программы. Сохраните список техники в JSON-файл. При запуске приложения данные загружаются из файла, при добавлении, редактировании и удалении — сохраняются.
[
  {
    "id": 1,
    "name": "Кировец К-744Р4",
    "category": "Трактор",
    "inventory_number": "TR-001",
    "year": 2022,
    "status": "Исправна",
    "location": "Машинный двор",
    "responsible": "Иванов И.И.",
    "hours": 840,
    "active": true,
    "condition": 86
  }
]
Работу с JSON желательно вынести в отдельный класс или модуль хранения данных. QML не должен самостоятельно открывать и переписывать файл.
12. Связь Python и QML
QML должен получать модель техники и обращаться к Python для операций, которые изменяют данные. Можно использовать QObject с @Slot, Signal и Property либо другой изученный способ организации моста.
QML:
пользователь нажал «Сохранить»
        ↓
Python @Slot
        ↓
проверка введённых данных
        ↓
EquipmentModel
        ↓
сохранение JSON
        ↓
Signal / обновление модели
        ↓
QML автоматически показывает изменения
Не требуется помещать всю бизнес-логику непосредственно в обработчик onClicked. QML собирает пользовательский ввод и сообщает о действии; Python решает, можно ли изменить данные.

·	Реализовано добавление новой техники.
